# Wallet — v1.0.8 (MVP)

Мобильное приложение учёта доходов и расходов на **1С:Предприятие 8.3.22**.

**Package:** `com.gmail.sekasid.mapp_wallet`  
**Ветка / тег:** `master` @ `e0d5ba3`

---

## Что умеет

### Учёт
- Доходы, расходы, переводы между счетами, долги (контакты)
- Счета (наличные / карта / банк), категории доходов и расходов
- Главный экран: остаток, сводка за период, последние операции
- Отчёты по доходам, расходам, долгам
- Мультивалютность и курсы валют (автообновление при старте или последний известный курс)

### Первый запуск и настройки
- Онбординг / выбор валюты учёта
- Справочники и операции через удобный мобильный UI

### Резервное копирование
- Локальная копия `WalletBackup_*.xml` (версия формата 1)
- Выбор папки для копий, далее автосохранение туда
- Восстановление из локального файла (с подтверждением)
- Копия в **Google Drive** и восстановление из Drive (OAuth Device Code через браузер)
- Client ID / Client Secret задаются в настройках приложения (константы)

### Безопасность
- PIN-код и биометрия (на поддерживаемых устройствах)
- Скрытие сумм (••••) на основных экранах
- Подтверждение при удалении счетов, категорий, контактов и документов
- Токены Google не хранятся открытым текстом

## Установка APK

1. Скачайте файл `*.apk` из Assets этого релиза.
2. Разрешите установку из неизвестных источников (если Android спросит).
3. Установите и откройте приложение.
4. При первом запуске завершите настройку валюты учёта.

> Это **не** сборка из Google Play — подпись debug/ваша; для теста и обратной связи.

---

## Как проверить за 5 минут

1. Создать счёт / категорию (если нужно).
2. Добавить доход и расход.
3. Убедиться, что остаток на главной обновился.
4. **Настройки → Резервное копирование** → выбрать папку → создать локальную копию.
5. (Опционально) Войти через Google → создать копию в Drive  
   — в Google Cloud должен быть включён **Google Drive API**, в OAuth — scopes `drive.file` + email, аккаунт в Test users.

## Известные ограничения (MVP)

- Нет нативного входа Google «как в обычном приложении» (системный выбор аккаунта) — нужна внешняя компонента; сейчас вход через **код в браузере** (Device Code).
- Темы оформления / полный онбординг этапа 16 — в отдельной ветке `themes`, в этот APK могут входить не все пункты.
- Публикация в Google Play и политики OAuth consent (Production) — ещё впереди.
- Автотесты UI не входят в релиз; приёмка — ручной прогон на устройстве.
